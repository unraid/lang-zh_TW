**識別資訊**：用來區分實體儲存裝置，包括型號、序號、Linux 裝置識別碼及容量。指派磁碟時，請務必比對序號，避免將錯誤磁碟指派至校驗磁碟或資料磁碟插槽。

**溫度**：從裝置取得的溫度。可在 [顯示設定](/Settings/DisplaySettings) 調整單位。為避免喚醒休眠中的硬碟，系統可能以 `*` 表示暫時無法取得溫度；部分 SSD 或 USB 裝置也可能無法提供可靠的溫度讀數，或回報 0。

**容量、已使用、可用**：顯示裝置容量及檔案系統的空間使用狀況，顯示單位可在 [顯示設定](/Settings/DisplaySettings) 調整。即使是空的檔案系統，也可能因中繼資料等開銷而佔用少量空間。對於多裝置儲存池，空間資訊可能反映整個儲存池，而非單一磁碟。

**讀取、寫入**：顯示磁碟 I/O 的統計計數，可在陣列操作區清除統計值。

**錯誤**：顯示裝置 I/O 錯誤。若陣列具有有效的校驗保護且故障數量未超過保護能力，Unraid 可透過其他磁碟重建缺失資料並模擬故障磁碟。無法復原的寫入錯誤可能導致磁碟被停用。請及時檢查磁碟、連接線及系統日誌。

**FS**：顯示裝置第 1 個分割區上偵測到的檔案系統。

**檢視**：磁碟已掛載時，可點選資料夾圖示瀏覽內容。

啟用「顯示陣列總計」後，會出現包含使用量、I/O 及平均溫度等資訊的總計列。

**陣列與校驗保護**

變更陣列磁碟指派前，必須先停止陣列。Unraid 陣列可使用零顆、一顆或兩顆校驗磁碟；若已設定校驗保護，校驗磁碟容量必須大於或等於容量最大的資料磁碟，並建議使用效能最高的磁碟。

與傳統條帶化 RAID 不同，Unraid 陣列的每顆資料磁碟具有自己的檔案系統。各資料磁碟也可分別匯出為共享資料夾。若磁碟故障數量超過校驗保護能力，仍可能遺失資料。**校驗保護不能取代備份。**

點選裝置名稱可以查看個別磁碟設定及相關維護工具。

**儲存池（Pool）** 與主陣列分開管理，可以由單一裝置或多個裝置組成，也可作為共享資料夾的儲存位置。使用 SSD 建立儲存池，通常能改善應用程式資料及經常存取檔案的效能。

**單一裝置儲存池** 可以使用 XFS、Btrfs 或 ZFS 等支援的檔案系統。單一裝置沒有磁碟備援能力；如果裝置損壞，尚未備份或移至其他位置的資料可能遺失。

**多裝置儲存池** 可使用 Btrfs 或 ZFS 等支援多裝置的檔案系統。資料保護方式取決於實際設定的 RAID／鏡像／RAIDZ 等配置，**不是只要放入多顆磁碟就一定具有備援能力**。新增、移除或重新配置磁碟前，請先備份重要資料並確認儲存池狀態。

在 [共享設定](/Settings/ShareSettings) 中，可以指定共享資料夾的主要與次要儲存位置，並設定 **Mover** 的搬移方向。Mover 可以依儲存政策在儲存池與陣列間移動檔案；它不是資料備份工具。

如需詳細資訊，請參閱 [Unraid 儲存池說明](https://docs.unraid.net/unraid-os/using-unraid-to/manage-storage/cache-pools/)。

:array_devices_help:
#### 指派磁碟

Unraid 主陣列由資料磁碟，以及選用的零顆、一顆或兩顆校驗磁碟組成。校驗磁碟用於磁碟故障後的資料重建，但不等同備份。

畫面上的 **陣列磁碟**（例如 disk1、disk2）是邏輯插槽；**實體硬碟** 則是指派至該插槽的裝置。實體裝置故障或遺失時，若校驗保護仍有效，Unraid 可能繼續模擬原本的邏輯磁碟內容。因此，指派裝置時，應以型號及**序號**確認磁碟身分，而不是只依 Linux 裝置名稱判斷。

若要變更指派，請先**停止陣列**，再從各磁碟插槽的下拉式選單選取裝置。指派變更會寫入系統設定。

#### 校驗磁碟的要求

Unraid 將檔案儲存在個別硬碟上，不會像傳統 RAID 將資料條帶化分散至所有裝置。寫入檔案時，會同時涉及目標資料磁碟與校驗磁碟。因此，除了下列容量要求，也建議優先選用效能較高的磁碟作為校驗磁碟。

- 每顆校驗磁碟的容量，都必須大於或等於**容量最大的資料磁碟**。
- 一顆校驗磁碟可保護單顆磁碟故障；兩顆校驗磁碟可在適當條件下容忍最多兩顆磁碟故障。
- 如果沒有設定校驗磁碟，或同時故障的磁碟超過保護能力，就無法依靠校驗資料重建遺失資料。
- 校驗保護並不能取代重要資料的異地或離線備份。

#### 建議操作步驟

1. 規劃校驗磁碟及各資料磁碟的用途，記錄每顆磁碟的型號與序號。
2. 安裝磁碟後，啟動 Unraid，進入 **Main** 頁面。新磁碟尚未指派時，可能會顯示在未指派裝置清單中。
3. 停止陣列後，依照實體磁碟的序號將裝置指派至正確的插槽。
4. 再次確認指派與容量條件，然後啟動陣列。

#### 熱插拔

如果控制器、背板及硬體支援熱插拔，您可以在系統持續通電的情況下連接或移除磁碟。不過，在變更陣列磁碟配置前仍須停止陣列，並遵循硬體的安全插拔程序。重新整理主頁後，新裝置會出現在指派用的下拉式選單中。

#### 後續步驟

確認磁碟指派無誤後，請依主頁的陣列狀態與操作提示啟動陣列。若要重建故障磁碟，應使用專用的重建流程，不要以「New Config」重設陣列設定。
:end

:encryption_help:
#### 加密金鑰輸入

陣列停止時，可以指定新的加密金鑰。裝置使用某個金鑰格式化後，必須使用相同金鑰才能解鎖。此處重新指定金鑰不會將既有資料自動轉換為新金鑰；若重新格式化加密裝置，**裝置上所有既有資料將永久遺失**。請勿將設定金鑰與格式化視為同一操作。

#### 密碼片語

可輸入最多 **512 個字元**的密碼片語。強烈建議只使用 [ASCII 字元表](https://en.wikipedia.org/wiki/ASCII) 前 128 個字元中的 95 個可列印字元，因為它們的二進位表示方式一致。其他字元可能因系統設定而使用不同編碼，導致密碼片語無法解鎖。若需要更長的密碼片語或包含二進位資料，請改用金鑰檔案。

如何選擇安全的密碼片語，請參閱 [cryptsetup FAQ](https://gitlab.com/cryptsetup/cryptsetup/wikis/FrequentlyAskedQuestions#5-security-aspects)。

**務必記住並妥善保存密碼片語。若所有可用的解鎖金鑰都遺失，加密內容將無法復原！**

#### 金鑰檔案

選擇儲存加密金鑰的本機檔案或二進位檔案。金鑰檔案大小上限為 **8 MiB（8,388,608 位元組；原文標示為 8M／8388608 byte）**。

**請備份金鑰檔案。若所有可用的解鎖金鑰都遺失，加密內容將無法復原！**
:end

:info_btrfs_balance_help:
**平衡（Balance）**會執行 `btrfs balance`，重新配置 Btrfs 儲存池的資料區塊或中繼資料區塊。此功能也可依可用選項變更 Btrfs RAID 配置，例如在 RAID1 和 RAID0 之間轉換。

**完整平衡**可能需要重新寫入大量資料，耗時取決於儲存池容量、使用量和磁碟效能。資料與中繼資料可以使用不同的 Btrfs 配置；**不要假設所有多磁碟儲存池都一定採用 RAID1**。

對於新建的多磁碟 Btrfs 儲存池，依版本及配置可能使用下列轉換選項：

`-dconvert=raid1 -mconvert=raid1`

**警告：將有備援的配置改成 RAID0 會失去磁碟備援能力。**變更配置或執行大型平衡作業前，請先備份重要資料，並確認目前的儲存池配置。

詳情請參閱 [Btrfs Balance 官方文件](https://btrfs.readthedocs.io/en/latest/btrfs-balance.html)。
:end

:smb_case_sensitive_names_help:
控製檔名是否區分大小寫。

使用預設設定**自動**時，支援區分大小寫檔名(Linux CIFSVFS) 的用戶端
可基於封包告知Samba 伺服器，它們希望以區分大小寫的方式
存取檔案系統（以支援UNIX 區分大小寫的語義）。Windows 系統不支援區分大小寫的檔名，因此
將該選項設定為**自動**的效果，與將其設定為“否”相同；但是，會保留Windows 用戶端傳遞的檔名的大小寫。對於大型目錄，此設定可能會導致
效能降低，因為Samba 必須進行檔名搜尋並匹配傳遞的名稱。

設定為**是**表示在用戶端通過的情況下建立檔案，並且只能使用相同的大小寫進行存取。
這將加快大型目錄的存取速度，但是使用此設定可能會令某些Windows 應用程式無法正常執行。
例如，如果建立了'MyFile'，但某個Windows 應用程式嘗試打開'MYFILE' （Windows 允許這種情況），會找不到該檔案。

**強制小寫**的值很特殊：所有傳入用戶端檔名（不僅是新檔名）都將設定為小寫。
換句話說，無論在Windows 端建立了何種大小寫混用的名稱，都將以全小寫來儲存和存取該名稱。
這樣可以確保所有Windows 應用程式正確查找無論大小寫如何的任何檔案，但大小寫不會保留在資料夾清單中。
請注意，僅應為新共享設定此設定。

:mgmt_use_ssl_tls_help:
設定區域網路上的網頁管理介面如何回應 HTTP 與 HTTPS 連線。

選擇**否**，使用未加密的 HTTP。可透過下列任一網址存取伺服器：

`http://<server-name>.<localTLD>`

`http://<server-ip-address>`

選擇**是**，啟用自動產生的自我簽署 SSL 憑證，並使用下列網址：

`https://<server-name>.<localTLD>`

自我簽署憑證會讓瀏覽器顯示警告。請先確認連線目標與憑證資訊。

選擇**嚴格（Strict）**，只允許使用 myunraid.net SSL 憑證透過 HTTPS 存取（請參閱下方的**佈建**說明）。此模式需要可連線的 DNS 伺服器。

**重新導向：**存取 `http://<server-ip-address>` 或 `http://<server-name>.<localTLD>` 時，行為依「使用 SSL/TLS」設定而異：

* **嚴格**：重新導向至 `https://<lan-ip>.<hash>.myunraid.net`。
* **是**：重新導向至 `https://<server-ip-address>` 或 `https://<server-name>.<localTLD>`。
* **否**：直接載入 HTTP 網址。

**重要：**若路由器或上游 DNS 伺服器啟用了 [DNS 重新繫結保護](https://en.wikipedia.org/wiki/DNS_rebinding)，可能無法選擇**嚴格**模式。這項保護會阻止 DNS 將網域解析至私人 IP 網段，用來保護區域網路中的裝置，尤其是網頁介面有漏洞或安全性不足的舊裝置。

保護機制可能來自網際網路服務業者（ISP）的 DNS 伺服器，也可能來自路由器。原文提及可改用其他 DNS 服務（例如 OpenDNS）或調整路由器設定；實際可用選項依目前服務與裝置版本而定。

部分家用路由器未實作此保護；有支援的路由器通常提供相關設定。較高階路由器常預設啟用，並可針對個別網域設定例外，或停用整體保護。**建議優先採用特定網域例外，保留其他網域的保護。**

**DD-WRT：**使用 dnsmasq 且已啟用重新繫結保護時，可在路由器設定檔加入：

`rebind-domain-ok=/myunraid.net/`

**pfSense：**使用內建 DNS 解析器服務時，可在自訂選項加入：

`server:`<br>
`private-domain: "myunraid.net"`

**Ubiquiti USG 路由器：**可加入下列設定：

`set service dns forwarding options rebind-domain-ok=/myunraid.net/`

**OpenDNS：**原文提供「Settings → Security」中取消勾選「Suspicious Responses - Block internal IP addresses」的做法。此選項會整體開啟或停用保護，無法只針對個別網域，變更前請評估影響。

其他方式無效時，可考慮在電腦的 *hosts* 檔案新增對應，覆寫外部 DNS，將伺服器的 myunraid.net 完整網域名稱（FQDN）直接解析至其區域網路 IP 位址。

**nginx 憑證檔案位置**依版本與設定可能包括：<br>
`config/ssl/certs/certificate_bundle.pem`<br>
`config/ssl/certs/<server-name>_unraid_bundle.pem`

憑證與私密金鑰請妥善保管，變更憑證時優先使用管理介面提供的功能。
:end

:mgmt_certificate_expiration_help:
**佈建（Provision）**可安裝由 [Let’s Encrypt](https://letsencrypt.org/) 提供的免費 myunraid.net SSL 憑證。

myunraid.net 憑證有兩種用途。第一種是讓伺服器透過下列替代網址回應連線：

`https://<lan-ip>.<hash>.myunraid.net`

`<hash>` 是伺服器專屬的 40 個十六進位字元字串（160 位元）。Lime Technology 的 DDNS 伺服器會在收到此網域的 DNS 查詢時，回傳您的 `<lan-ip>`。憑證主體設為 `*.<hash>.myunraid.net`，用來驗證 HTTPS 連線。

將**使用 SSL/TLS**設為**嚴格（Strict）**，可讓區域網路只使用此網址。

第二種用途是搭配 Unraid Connect 外掛程式提供安全的遠端存取。安全的遠端存取可以與未加密的本機存取並存。

安裝 myunraid.net SSL 憑證後，會啟用下列背景服務：

* **renewcert**：伺服器重新啟動完成 60 秒後，會聯絡 Lime Technology 憑證更新服務，確認憑證是否需要更新；之後每 24 小時檢查一次。到期前 30 天內，系統會自動佈建新憑證並下載至伺服器。

**刪除（Delete）**可移除 myunraid.net 憑證檔案。

**nginx 憑證處理細節**

nginx 使用 USB 開機裝置上的兩個憑證檔案：

* 自我簽署憑證：`config/ssl/certs/<server-name>_unraid_bundle.pem`
* myunraid.net 憑證：`config/ssl/certs/certificate_bundle.pem`

nginx 啟動時會自動建立自我簽署憑證；伺服器主機名稱或本機頂層網域（TLD）變更時，也會重新建立。

**nginx 的 OCSP Stapling 支援**

若憑證包含 OCSP 回應伺服器網址，系統會自動啟用 OCSP Stapling。因此自我簽署憑證不會啟用；由憑證授權單位（CA）簽署且包含該網址的憑證則會啟用。

**DNS 保護提醒：**若佈建時遇到 DNS 重新繫結保護，請先確認網域解析與路由器設定，並優先使用特定網域例外，保留其他網域的保護。實際申請條件與更新機制請以使用中的 Unraid 版本為準。
:end

:eth_bonding_mode_help:
**模式 0：循序負載平衡（balance-rr）**

依序透過各成員介面傳送封包。例如有兩個介面時，第 1、3 個封包使用第一個介面，第 2、4 個封包使用第二個介面。可提供負載平衡與容錯。

**模式 1：主動／備援（active-backup，預設）**

同一時間僅使用一個介面；作用中的介面連線中斷時，改由備援介面接手。此模式提供容錯。

**模式 2：XOR 負載平衡（balance-xor）**

依來源與目的地 MAC 位址的 XOR 運算結果選擇成員介面；相同目的地通常使用相同介面。可提供負載平衡與容錯。

**模式 3：廣播（broadcast）**

透過所有成員介面傳送每一個封包，主要用於特殊容錯需求，不提供一般負載分流。

**模式 4：IEEE 802.3ad 動態鏈路聚合**

將速度與雙工設定相同的介面組成聚合群組，交換器也必須支援並正確設定 IEEE 802.3ad。傳出流量依 `xmit_hash_policy` 選擇介面。並非所有雜湊原則都符合 802.3ad 的封包順序要求（第 43.2.4 節），不同對端裝置對不合規情況的容許程度也不同。

**模式 5：適應性傳送負載平衡（balance-tlb）**

依各成員介面的負載分配傳出流量；傳入流量由目前作用中的介面接收。

**模式 6：適應性負載平衡（balance-alb）**

結合 balance-tlb 與 IPv4 接收負載平衡。透過 ARP 協商，以不同成員介面的 MAC 位址回應不同用戶端，分散傳入流量。

**一般建議使用模式 1。其他模式可能需要交換器配合設定；選擇不受支援的模式可能導致網路中斷。**
:end

:apc_ups_type_help:

:apc_ups_device_help:

- **snmp**：`hostname:port:vendor:community`。hostname 為 UPS 的主機名稱或 IP 位址；vendor 通常為 `APC`，使用 `APC_NOTRAP` 可停用 SNMP Trap 接收；連接埠通常為 161，community 通常為 `private`。

- **pcnet**：`ipaddr:username:passphrase:port`。依序為 UPS 管理卡的 IP 位址、使用者名稱、密碼及接收 UPS 訊息的連接埠。省略連接埠時使用預設值 3052。

:nfs_security_rules_help:

請勿使用 IP1,IP2(...) 格式輸入多個位址，因為 Unraid 不會以此方式產生 NFS exports 檔案。
