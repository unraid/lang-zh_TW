:tips_tweaks_general_plug:
> 一般建議：
>
> * 某些情況使用固定 IP 位址較有幫助，NFS 共享資料夾是以 IP 位址參照。請在路由器保留該位址，或選擇不會與 DHCP 動態配發範圍重疊的位址，以免衝突。
> * 不建議使用巨型訊框（Jumbo Frames），部分 Docker 容器可能因此發生問題。
> * 除非 Unraid 伺服器有不斷電系統（UPS）保護，否則請勿將 `vm.dirty_ratio` 設為超過 20%。停電時，尚未寫入磁碟的資料可能遺失。
> * 不建議將 `vm.dirty_background_ratio` 設為超過 `vm.dirty_ratio` 的一半，除非兩個值都是個位數。
:end

:tips_tweaks_nic_flow_control_plug:
> 設為**是**，停用網路卡流量控制。此功能原本用於協調混合不同速率裝置的網路，現代網路未必需要。
>
> 網管型交換器通常可直接開啟或關閉流量控制；一般家用交換器可能無法調整。某些情況下，流量控制可能造成網路問題，若遇到相關問題，可考慮停用。
>
> **從任何設定改回「預設」後，都需要重新啟動。**
:end

:tips_tweaks_nic_offload_plug:
> 設為**是**，停用網路卡運算卸載。此功能將部分網路處理工作由 CPU 移交網路卡，並處理大型封包，以減輕 CPU 負擔及提高網路傳輸量。
>
> 某些情況下，TSO 運算卸載可能造成網路問題。若遇到相關問題，可考慮停用網路卡運算卸載。
>
> **從任何設定改回「預設」後，都需要重新啟動。**
:end

:tips_tweaks_rx_buffer_plug:
> 設定網路卡 Rx 接收環狀緩衝區大小，部分網路卡有硬體上限。通常建議維持預設 256；由其他值恢復成預設值可能需要重新啟動。
:end

:tips_tweaks_tx_buffer_plug:
> 設定網路卡 Tx 傳送環狀緩衝區大小，部分網路卡有硬體上限。通常建議維持預設 256；由其他值恢復成預設值可能需要重新啟動。
:end

:tips_tweaks_nics_plug:
> 輸入要套用設定的網路介面名稱，以逗號分隔。若使用網路介面繫結（Bonding），請包含所有成員介面。
:end

:tips_tweaks_dirty_background_plug:
> 建議將 `vm.dirty_background_ratio` 設為 3%、`vm.dirty_ratio` 設為 5%。若記憶體容量很大，可分別設為 1% 與 2%。
>
> **注意：除非有能可靠地讓 Unraid 正常關機的 UPS，否則請勿將這些值提高至超過預設值，以免斷電時遺失尚未寫入磁碟的資料。**
>
> `vm.dirty_background_ratio` 是尚未寫回磁碟的資料占**總記憶體**的百分比，達到門檻時開始背景回寫。除非記憶體容量很大，否則建議保留預設的 3%；若執行媒體串流或遊戲虛擬機器，可使用 1%。
:end

:tips_tweaks_dirty_ratio_plug:
> 設定 `vm.dirty_ratio`，表示尚未寫回磁碟的資料占**總記憶體**的百分比。
>
> 設定過高可能使 Linux 為了取得更多記憶體而終止部分處理程序。除非記憶體容量很大，否則建議保留預設的 **5%**。
:end

:tips_tweaks_cpu_governor_plug:
> 選擇一般運作時使用的 CPU 頻率調節器：
>
> * **省電（Power Save）**：將 CPU 固定在最低頻率，以盡量節省電力。
> * **隨需調整（On Demand）**：ACPI CPUFreq 驅動程式的預設模式，依負載積極調整頻率。
> * **保守（Conservative）**：依負載較緩和地調整頻率，可能增加延遲。
> * **效能（Performance）**：不論負載，將 CPU 固定在最高頻率，可改善效能與延遲。
> * **Schedutil**：透過 Linux 排程器依負載調整 CPU 頻率。
>
> 也可使用 `rc.tweaks` 指令碼設定調節器：
>
> `/usr/local/sbin/rc.tweaks set_governor 'governor'`
>
> 將 `governor` 替換為 `ondemand`、`performance`、`powersave`、`conservative` 或 `schedutil`。可用模式取決於 CPU 與驅動程式。
:end

:tips_tweaks_power_save_cpu_governor_plug:

>
> * **省電（Power Save）**：將 CPU 固定在最低頻率，以盡量節省電力。
> * **隨需調整（On Demand）**：ACPI CPUFreq 驅動程式的預設模式，依負載積極調整頻率。
> * **保守（Conservative）**：依負載較緩和地調整頻率，可能增加延遲。
> * **Schedutil**：透過 Linux 排程器依負載調整 CPU 頻率。
:end
